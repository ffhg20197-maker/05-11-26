# CI/CD — учебный веб-проект

Практическая работа по теме 3.1.44 «Рассматривать этапы непрерывной интеграции и публикации веб-проектов», дисциплина «Автоматизировать процесс DevOps».

## Состав проекта

- `index.html` — адаптивная учебная страница о DevOps, CI, CD, жизненном цикле веб-проекта, безопасности и проверке после публикации.
- `style.css` — оформление и адаптивная сетка.
- `script.js` — интерактивный чек-лист проверки опубликованного сайта.
- `.github/workflows/ci.yml` — CI: проверка обязательных файлов при push и pull_request.
- `.github/workflows/deploy.yml` — CD: подготовка артефакта и развертывание на GitHub Pages.

## Этап CI

Workflow **Web project CI** запускается при push в ветку `main` и при pull_request в `main`. Он получает код через `actions/checkout@v4` и проверяет наличие `index.html`, `style.css`, `script.js`. Если файл отсутствует, команда `test -f` завершится ошибкой и job получит статус `failure`.

## Этап CD

Workflow **Deploy to GitHub Pages** повторно проверяет файлы и ссылки на стили/скрипты, настраивает Pages, загружает файлы как артефакт и публикует их через `actions/deploy-pages@v4`.

**Однократная настройка владельца репозитория:** откройте **Settings → Pages → Build and deployment → Source**, выберите **GitHub Actions**. После этого workflow сможет завершить публикацию. В текущем запуске GitHub вернул `Resource not accessible by integration` при попытке включить Pages автоматически; workflow и файлы проекта готовы, но эта настройка требует разрешения владельца репозитория.

## Проверка практического задания

1. Откройте вкладку **Actions** и проверьте workflow **Web project CI**.
2. Для демонстрации ошибки создан учебный pull request №1, в котором временно отсутствовал `style.css`. CI обнаружил отсутствие файла и завершился с ошибкой.
3. После демонстрации `style.css` восстановлен в ветке демонстрации. Pull request закрыт без слияния; основная ветка `main` не повреждена.
4. После выбора GitHub Actions в Settings → Pages повторно запустите **Deploy to GitHub Pages** или отправьте новый commit.
5. Откройте опубликованный адрес и проверьте главную страницу, стили, скрипты, меню, мобильный вид и основные действия.

## Безопасность

В репозитории не хранятся пароли, API-ключи и токены. Workflow использует разрешения, необходимые для чтения репозитория и публикации Pages. Перед выпуском production-версии следует ограничить доступ к среде, проверить Actions и предусмотреть резервную копию/откат.

## Отчёт

В отчёт необходимо добавить ФИО студента, группу, название темы, ссылку на репозиторий, скриншоты структуры файлов и результатов CI, описание подготовки к публикации, ссылку на опубликованный сайт (после активации Pages), скриншот сайта и вывод о роли CI/CD.
