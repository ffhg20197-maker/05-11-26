# CI/CD — учебный веб-проект

Практическая работа по теме 3.1.44 «Рассматривать этапы непрерывной интеграции и публикации веб-проектов», дисциплина «Автоматизировать процесс DevOps».

## Состав проекта

- `index.html` — учебная страница о DevOps, CI, CD, жизненном цикле веб-проекта, безопасности и проверке после публикации.
- `style.css` — оформление и адаптивная сетка.
- `script.js` — интерактивный чек-лист.
- `build.mjs` — автоматическая сборка статического сайта в каталог `dist/`.
- `tests/site.test.mjs` — автоматические проверки структуры и поведения проекта.
- `.github/workflows/ci.yml` — CI при push и pull_request.
- `.github/workflows/deploy.yml` — повторные тесты, сборка и публикация на GitHub Pages.

## Пять принципов CI из видеоматериала

1. **Version Control** — Git хранит историю изменений, GitHub — удалённый репозиторий.
2. **Build Automation** — команда `npm run build` автоматически формирует папку `dist/`.
3. **Test Automation** — команда `npm test` запускает тесты Node.js.
4. **Often Commits** — изменения рекомендуется отправлять небольшими частыми коммитами.
5. **Build on Change** — GitHub Actions автоматически запускает CI после каждого push; для pull request в main также запускаются проверки.

## Этап CI

Workflow **Web project CI** получает код через `actions/checkout@v4`, устанавливает Node.js 22, запускает автоматические тесты и собирает сайт. Затем проверяет, что в `dist/` находятся `index.html`, `style.css` и `script.js`. Если тест или проверка не проходит, job завершается со статусом failure.

Тесты проверяют:
- наличие обязательных файлов;
- язык HTML-документа, viewport и подключения CSS/JavaScript;
- наличие разделов жизненного цикла, CI и публикации;
- наличие чек-листа и обработчика пользовательского действия.

## Этапы тестирования

На схеме из видеоматериала показаны Unit Tests, WS Tests и UI Tests. В текущем учебном проекте реализованы автоматические проверки файлов, структуры HTML и интерактивного чек-листа. Отдельного backend/API у этого статического сайта нет, поэтому реальные WS/API-тесты неприменимы и не имитируются. Проверка интерфейса сейчас выполняется на уровне структуры HTML и наличия интерактивных элементов; полноценный браузерный UI/E2E-тест можно добавить при необходимости.

## Этап CD

Workflow **Deploy to GitHub Pages** повторно запускает тесты и сборку, загружает только каталог `dist/` как артефакт и публикует его через `actions/deploy-pages@v4`. Публикация запускается при push в `main` или вручную через Actions.

**Однократная настройка владельца репозитория:** откройте **Settings → Pages → Build and deployment → Source**, выберите **GitHub Actions**. Если GitHub не разрешает workflow включить Pages автоматически, эту настройку необходимо сделать в интерфейсе репозитория. До успешного запуска deploy workflow сайт нельзя считать опубликованным.

## Проверка практического задания

1. Откройте вкладку **Actions** и проверьте workflow **Web project CI**.
2. Убедитесь, что job прошёл тесты и сборку.
3. Для демонстрации ошибки ранее создан учебный pull request №1, в котором временно отсутствовал `style.css`. CI обнаружил отсутствие файла; PR закрыт без слияния, основная ветка не повреждена.
4. Проверьте workflow **Deploy to GitHub Pages** после выбора GitHub Actions в Settings → Pages.
5. Откройте опубликованный адрес и проверьте главную страницу, стили, скрипты, меню, мобильный вид и чек-лист.

## Безопасность

Не хранить пароли, API-ключи и токены в репозитории. Использовать GitHub Secrets и минимальные разрешения workflow. Для production-системы предусмотреть резервную копию, мониторинг и план отката к предыдущей стабильной версии.

## Отчёт

В отчёт добавить ФИО, группу, ссылку на репозиторий, скриншоты успешного CI и демонстрации ошибки, описание сборки и публикации, ссылку на сайт после успешного deploy и вывод о роли CI/CD.
