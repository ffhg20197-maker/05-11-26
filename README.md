# CI/CD — учебный веб-проект

Практическая работа по теме «Этапы непрерывной интеграции и публикации веб-проектов».

## Структура проекта
- `index.html` — главная страница.
- `style.css` — адаптивные стили.
- `script.js` — интерактивный чек-лист проверки сайта.
- `.github/workflows/ci.yml` — CI: проверка обязательных файлов при push и pull_request.
- `.github/workflows/deploy.yml` — CD: публикация в GitHub Pages.

## CI
Workflow **Web project CI** получает код через `actions/checkout@v4` и проверяет наличие `index.html`, `style.css`, `script.js`. Если файл отсутствует, команда `test -f` завершится ошибкой и job получит статус failure.

## CD
Workflow **Deploy to GitHub Pages** загружает файлы сайта как artifact и публикует их через официальные actions GitHub Pages.

## Проверка
1. Откройте вкладку **Actions** и дождитесь успешного выполнения обоих workflow.
2. В настройках репозитория откройте **Settings → Pages**. Источник публикации должен быть **GitHub Actions**.
3. Откройте адрес опубликованного сайта и проверьте главную страницу, стили, скрипты, ссылки и мобильный вид.
4. Для демонстрации ошибки CI временно измените имя одного из обязательных файлов, отправьте commit и убедитесь, что CI завершился с ошибкой. Верните имя файла и отправьте исправление.

## Безопасность
В репозитории не хранятся пароли, API-ключи и токены. Workflow использует минимально необходимые разрешения для чтения репозитория и публикации Pages.
